# Portfolio — Agent Guide

**Vue 3 + TypeScript + Tailwind v4**, built with **Vite+** (not plain Vite). Single-page portfolio, no router, no Nuxt.

---

## Commands (Vite+ CLI — `vp`)

| Action                       | Command                                          |
| ---------------------------- | ------------------------------------------------ |
| Dev server                   | `vp dev`                                         |
| Format + lint + typecheck    | `vp check`                                       |
| Lint only                    | `vp lint` / `vp lint .` (package script)         |
| Tests (watch)                | `vp test`                                        |
| Tests (once)                 | `vp test --run`                                  |
| Build (full, with typecheck) | `pnpm run build` (runs `tsc -b` then `vp build`) |
| Build (vite+ only)           | `vp build`                                       |
| Preview build                | `vp preview`                                     |

- `vp` is a global CLI provided by the Vite+ dependency — all commands use it directly.
- Pre-commit hook (`.vite-hooks/pre-commit`) runs `vp staged`, which applies `vp check --fix` to staged files (configured in `vite.config.ts`).

## Testing

- **Import from `vite-plus/test`**, not `vitest`: `import { describe, it, expect, vi } from "vite-plus/test"`
- Co-locate `*.spec.ts` next to the source file (e.g. `useScramble.spec.ts` beside `useScramble.ts`)
- Singleton composables (`useTheme`): call `vi.resetModules()` + dynamic `import()` per test to avoid state leakage
- Composables needing Vue lifecycle (`onMounted`, `watch`): wrap in `defineComponent` + `mount` (see [testing.instructions.md](.github/instructions/testing.instructions.md) for the `withSetup` helper)
- Mocks required: `window.matchMedia` (for `useScramble` / `useTheme`), `localStorage` (for `useTheme`)
- Fake timers: `vi.useFakeTimers()` for animation composables (`useScramble`)

## TypeScript Constraints

- `erasableSyntaxOnly: true` — **no `enum` or `namespace`**
- No path aliases (`@/`) — all imports are relative
- `strict: true`, `noUnusedLocals`, `noUnusedParameters`
- `@vue/test-utils@2.4.11` has broken type declarations; a `paths` override in `tsconfig.app.json` redirects to the real types. This is transparent in practice — only matters if TS7016 appears.

## Build / Deploy

- CI: **Woodpecker** on push to `main`. PR events only run `validate` (check + test).
- Pipeline: `validate → build → deploy` (Codeberg Pages via SSH).
- CI shares workspace volume — `pnpm install` runs once in `validate`, `node_modules` persists to later steps.
- In CI, use `pnpm run <script>` (not `vp`) — the CLI isn't global in the Docker container.
- Production security headers (`CSP`, `HSTS`, `COOP`, `COEP`, etc.) are generated by `productionCSP()` in `vite.config.ts` — **edit headers only there**. The plugin emits `dist/_headers` (Netlify format) and injects a CSP `<meta>` tag at build time.
- `dist/_headers` is auto-generated — never edit it directly.
- The full `dist/` output (including the auto-generated `dist/_headers`) is gitignored — only source is committed. Build artifacts regenerate on every `vp build`.

## Toolchain quirks

- **pnpm `overrides` + `resolutions` alias `vite` and `vitest`** to `@voidzero-dev/vite-plus-core` and `@voidzero-dev/vite-plus-test`. This is required for Vite+ and is intentional — `pnpm install` warnings about these packages are expected.
- **`opencode.json` enables `Astro docs` and `nuxt` MCP servers** that are not relevant to this Vue 3 + Vite+ project. Don't invoke them; the actual framework is Vue 3 with the Vite+ CLI (`vp`).

## When things go wrong

- Run `vp env doctor` to diagnose toolchain / runtime / package-manager issues (per Vite+ guidance in `.github/copilot-instructions.md`).
- Run `vp install` after pulling remote changes or switching branches — the Vite+ wrapper manages state outside `pnpm install`.

## Architecture Notes

- **Entry**: `src/main.ts` → `src/App.vue` (single page, no router — sections scroll in-view)
- **Data**: `src/data/portfolio.ts` — edit this file to add projects, skills, social links (typed in `src/types.ts`)
- **Theme**: Tailwind v4 with `@theme` in `src/style.css`. Semantic utilities: `bg-canvas`, `bg-card`, `text-primary`, `text-secondary`, `text-accent`, `border-border`. Dark mode via `.dark` class on `<html>`, managed by `useTheme` composable.
- **Icons**: `@lucide/vue` for standard icons, custom SVG components (`IconCodeberg.vue`, etc.) for social logos
- **Font**: JetBrains Mono, self-hosted (woff2 in `src/assets/jetbrains_mono_webfonts/`)
- **PWA**: `vite-plugin-pwa` configured in `vite.config.ts` — `registerType: "autoUpdate"`
- **`vite.config.ts` split avoidance**: The config is intentionally split into `toolingConfig` + `vitePlugins` + `mergeConfig` to avoid TS2321 recursion limit on Vite+ types. Do not collapse into a single `defineConfig()` call.
